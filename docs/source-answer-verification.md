# Source-answer verification (targeted P1 scaffold repair)

This change addresses two independently observed weaknesses of Nestra P1 + LocalPilot after the earlier scaffold repairs: inaccurate numerical/constants citations and incomplete explanations of repository integration.

**Numeric attribution.** If Nestra explicitly states a named code constant or parameter and a numeric value in a repository explanation, the final-answer gate verifies that the exact symbol and value appear together on an inspected source line. Unrelated values on another file/line are not proof. Source line citations (`path/file.py:123`) are accepted only when the corresponding line was returned by a successful trusted `read_repository_file` or `search_repository` result. When the owner asks for repository citations, the answer must supply checked line references or acknowledge what was not inspected.

**Cross-file reasoning.** The model is instructed to identify the actual entrypoint, read-only or action authority boundary, callee and return/effect from the inspected code. The gate rejects an assertion that a cross-module trace is complete when the only available inspected evidence is from a single file and the answer doesn't explicitly limit its scope. A lack of evidence remains *unverified*, not proof of absence.

**Narrow scope and limitations.** These rules apply only to source-code questions with inspected repository text. They are not a general factual or numerical truth oracle. They do not classify normal prose numbers, infer missing control flow, validate business figures, or convert an illustrative number supplied by the owner into a live repo claim. Statements of uncertainty and qualified incomplete answers remain allowed. Same-source-line binding cannot always distinguish a parameter default from a maximum, so guidance specifically instructs the model to separate the two and the owner should inspect key conclusions.

**Safety and reproducibility.** No P1 weights, frozen datasets, historical reports, tool permissions, action-execution authorization, promotion rules, or runtime generation budget changed. Regression tests cover supported and mismatched constants, swapped file/line citations, hypothetical numeric premises, missing evidence, scope-qualified answers, and incomplete call-chain claims. Complete GitHub CI must pass before merge. After merge, check new independently written source-answer problems on the fixed P1 digest before starting the full 684-cell comparison.
